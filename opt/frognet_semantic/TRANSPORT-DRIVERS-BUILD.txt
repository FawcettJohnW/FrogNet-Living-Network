FrogNet transport drivers, build of 18 November 2026
branch homa-under-croakos-20261116, code as of commit 8b80d447 (base 948b435c)

What this is
  The semantic wire's transport as drivers: tcp (as before), softhoma (Homa's DATA frames on a TCP connection the
  driver holds open, port 9131), homa (the kernel module, where it is loaded). The setting is per RAM connection.
  core/TRANSPORT-DRIVER-INTERFACE.md says what a driver is.

Until it is turned on, a node runs on TCP as it did.
  With no /etc/frognet/semantic_transport the word is auto, and auto on a node without Homa in its kernel is tcp.
  Also in this build, on TCP: the engine's session is split from the TCP sockets (same bytes on the wire); a request
  is no longer refused as "reader dead" while its own session is still starting; a retry after REQ_MISS is its own
  frame; a request frame says its field order (18 bytes more; nodes on the code before this read it unchanged, and
  this code reads theirs, so nodes can be upgraded one at a time).

To turn soft Homa on for the connection to the SystemRam, on EVERY node (the role moves, so every node needs it):
  /etc/frognet/semantic_transport holds two lines:
      tcp
      databasehost.frognet softhoma
  then restart frognet-daemon and frognet-proxy. To turn it off, remove the file and restart them.
  A node whose setting names softhoma listens on TCP 9131 as well as 9009. A link that filters by port must let 9131
  through: usr/local/bin/ham_guardrail.sh lets only 9009 through on ham links and is NOT changed by this build.

What the logs say, so nothing has to be run to find out
  [SEM-TRANSPORT] ... carriers here: ...      what this node carries the wire on, at start
  [HOMA] ... build=homa-frames-on-tcp-v3-20261118c on SOFT HOMA ...      each end that opens soft Homa
  [SOFTHOMA] ... the connection to <ip>:9131 is open; it is held open
  [WIRE-METRICS] ...                          where the time goes in the Homa driver, by frame size

Tested in the simulator: 20 topologies, perfect links, four batteries each (fan-out between every pair, frames of
1,000 to 3,000,000 characters, the door's scenarios, a machine leaving and returning):
  tcp                                             20 of 20   1,516 checkpoints
  softhoma                                        20 of 20   1,574
  softhoma, with databasehost_control.frognet tcp 20 of 20   1,574
  tcp, with databasehost.frognet softhoma         20 of 20   1,536   (the setting given above)
and 13 driver gates. NOT tested: on real nodes; kernel Homa on a real machine; shaped (slow, lossy) links on this
code.
