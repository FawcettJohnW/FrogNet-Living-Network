FrogNet site — repackaged bundle (rev 23 · 2026-07-13)
======================================================
Base: frognet-site-rev22. Product-accuracy pass + form receiver hooked up.

APPLIED
- UnREST Programming Models(.dc.html and -print.dc.html), Diagram 8: retired the
  dead "vouch" model. SVG label "promote · vouch" -> "promote · prove"; caption
  "...an unreachable network is vouched for by a relay." -> "...a network you
  can't reach directly is carried by a relay that has itself proven the onward
  path." Brings both pages in line with prove-then-route (DOCTRINE: liveness is
  the :9009 ping-pong; a getHosts claim is not proof). These were the only two
  stale spots; build_magnum.js and the rest of the site were already correct.
- SERVE THE SITE THROUGH THE NODE (eat our own cooking). On a FrogNet node the
  proxy owns :80 and forwards local web content to Apache on 127.0.0.1:8080,
  handing each exchange to the :9009 daemon. So the site rides the proxy+daemon
  by being what that Apache serves. The deploy config for this lives OUTSIDE the
  webroot as frognet-site.apache.conf (DocumentRoot -> this bundle; /api/ reverse-
  proxied to the license receiver). frognet_site.py is included as a DEV-ONLY
  convenience (serves site + receiver on one port for local testing); it BYPASSES
  the proxy/daemon and must not be used on a node.
- license_endpoint.py header comment corrected: the receiver belongs on the WEB
  SERVER, not the broker. It is website form-handling (store + sendmail) with no
  shared state or data path with node introduction/tunnel minting. NOTIFY_TO and
  SENDMAIL remain the two lines to set before going live. (Open item, not yet
  patched: the name/country fields reach the mail Subject and CTRL_RE does not
  block CR/LF, so a crafted field can inject headers; sanitize before launch.)
