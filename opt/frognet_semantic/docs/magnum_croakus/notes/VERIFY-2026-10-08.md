## Part III — Hooking Up the Network (06_Part_III_Hooking_Up_the_Network.md)

1. **Where**: §5 "Wired Ethernet" worked example, and §7 "Forming, then splitting"
   **Text**: "plug both boxes into the same switch and they share a segment ... sees the other as an immediate peer" (HomeBase 10.80.80.1, ShopBox 10.84.84.1)
   **Verdict**: UNSUPPORTED (and very likely WRONG)
   **Evidence**: Each node holds the .1 of its own /24 on eth0 and runs DHCP on it (frognet-netstart:160-180, 299-301), so the switch would carry two /24s and two DHCP servers. Discovery finds immediate peers only through DHCP leases on its own subnet, 10.x ARP neighbours, or the .1 of a subnet where it holds a non-.1 lease (discovery/discovery.py:1150-1206). Nothing finds a foreign subnet's .1 on the same wire. The simulator rejects this shape: topo_pair needs a separate shared peering /24 and says the one-/24 version "was invalid" (simulation/frognet_sim.py:945-957). John, 2026-05-12 (b0df173f): "Nodes connect to each other as wifi -> eth0, or something similar." John, 2026-07-12 (b8e7ee1d): "A FrogNetHost will only serve one network."
   **Fix**: "Cable ShopBox's eth0 (or Wi-Fi) to HomeBase's served segment so it takes a lease from HomeBase. The next walk on HomeBase sees it as an immediate peer through that lease." Make the same change in the §7 example.

2. **Where**: §6 "Resolving names, and the default route", paragraph 2
   **Text**: "writes the result into /etc/hosts, but only its own lines ... leaves everything else in the file untouched"
   **Verdict**: WRONG
   **Evidence**: build_etc_hosts returns a fixed header, "127.0.0.1 localhost", and the normalized 10.x FrogNetHost./FrogNetAdmin. lines, and nothing else (discovery/hosts.py:39-44, 162-190). _commit_hosts then writes that list over the whole /etc/hosts (discovery/live.py:1135-1153). Any other line is dropped, including the installer's 127.0.1.1 line (installer E2, frognet_install.sh:1705-1706) and bare short names.
   **Fix**: "Discovery owns /etc/hosts. On every merge it rewrites the whole file from the walk's result (localhost plus the FrogNet peer and role lines), so do not keep hand entries there."

3. **Where**: §6 "Resolving names, and the default route", paragraph 3
   **Text**: "the default route, and FrogNet leaves it alone on purpose ... Discovery installs routes only for the mesh ... the untouched default route"
   **Verdict**: WRONG
   **Evidence**: Every merge runs FixDefaultRoute (discovery/live.py:819; discovery/fixdefault.py:19-38). It purges dead defaults, installs off-LAN defaults at metric 601, and in Mode B builds a ranked default-route ladder through a peer that advertises an exit. In that file's own words, "the default route walks the mesh out to the WAN edge one hop at a time". John, 2026-05-22 summary (accef35e): "the pond has Internet if any node does, managed automatically by fixDefaultRoute every merge cycle".
   **Fix**: "Discovery manages the mesh's 10/8 routes, and it also keeps the default route working. A node with its own uplink keeps it, dead defaults are pruned, and a node without an uplink takes its default through a peer that advertises a live exit. Non-mesh traffic leaves by that default."

4. **Where**: §5 "Onboard Wi-Fi" worked example
   **Text**: "This switch governs only the node's own onboard radio."
   **Verdict**: WRONG
   **Evidence**: Projection runs on AP_IFACE, which can be wlan1, "an external USB adapter with a directional antenna" (frognet_install.sh:1949-1950 and the --ap-iface option; frognet-netstart:222-230, 286).
   **Fix**: "This switch governs only the radio the node projects its own SSID on (AP_IFACE, wlan0 by default)."

5. **Where**: §5 "Onboard Wi-Fi" worked example
   **Text**: "Set the preference with the v4 setup helper and frognet-netstart honors it on its next run" (and §11 lists country as "via helper/page")
   **Verdict**: WRONG
   **Evidence**: ssid_projection_set calls frognet-ssid-projection. That script re-runs netstart immediately and masks hostapd on "off" (frognet-ssid-projection:69-89). Its _write_state rewrites the whole file with only SSID_PROJECTION=, which deletes AP_IFACE and WIFI_COUNTRY (frognet-ssid-projection:54-66). Netstart then falls back to wlan0 and US (frognet-netstart:99-104, 216-224).
   **Fix**: "...the helper applies it at once (it re-runs frognet-netstart). The helper sets only on/off, and in this build it also resets the AP interface and country to wlan0/US."

6. **Where**: §5 "Onboard Wi-Fi"

   **Fix**: "A link watcher (ifplugd) fires it a few seconds after you plug or unplug."

7. **Where**: §6 "The four scopes"
   **Text**: "Chorus is a named group of nodes ... the circle the broker actually meshes over the internet"
   **Verdict**: WRONG (incomplete)
   **Evidence**: John, 2026-05-22 (accef35e): "There is the pond-sized chorus of all lillypads, and there are subnet choruses controlled by the admin." Chorus is a group of Lillypads. Not every chorus is named, and a chorus is not defined by the broker.

## Part V — Discovery (08_Part_V_Discovery.md)

16. **Where**: §13 "We Eat Our Own Cooking", intro, and "The proxy owns port 80" paragraph 1
    **Text**: "Both are plain HTTP, both compressed by the same engine as everything else" / "discovery's own echo and getHosts calls — arrives at the proxy first ... That is why discovery gets the compression and the transport for free"
    **Verdict**: WRONG
    **Evidence**: The real echo and getHosts use MarkedHTTPConnection with SO_MARK=1, so the iptables rule RETURNs and the request bypasses the local proxy and the semantic RPC ([ECHO_SOMARK_DIRECT_V1], [GETHOSTS_SOMARK_DIRECT_V1], discovery/real_backends.py:107-131, 161-183; etc/setup_iptables:77). They go directly to the neighbour's port 80 on the discovery plane, uncompressed. This was changed 2026-07-10 (chat 551236bb). Liveness is the :9009 ping-pong. The "4800-baud" sentence that depends on this falls with it.
    **Fix**: "Both are plain HTTP to the neighbour's port 80. Discovery deliberately sends them direct, marked to bypass the local semantic proxy, so a walk never queues behind production traffic. Reachability itself is proved by the :9009 ping-pong."

17. **Where**: §13 "The proxy owns port 80", paragraphs 1-2
    **Text**: "Every HTTP request crossing the node's interface ... arrives at the proxy first" / "A request addressed anywhere else ... is simply passed through ... The proxy is in the path for everything"
    **Verdict**: WRONG
    **Evidence**: Only TCP/80 to 10.0.0.0/8 is redirected: OUTPUT, plus PREROUTING on LAN_IFACE (etc/setup_iptables:77-80). Non-10 HTTP never reaches the proxy, and SO_MARK=1 traffic bypasses it. The proxy's HAM/raw branch exists, but nothing feeds it non-10 traffic through interception.
    **Fix**: "HTTP to any 10/8 address is redirected into the proxy. HTTP to anywhere else is never intercepted and leaves by the normal route."

18. **Where**: §13 "The proxy owns port 80", paragraph 3

The proxy opens a standing socket to the destination peer's daemon, not a loopback socket to its own.
    **Fix**: "For a FrogNet-bound request, the proxy opens (and keeps) a socket to the destination node's daemon on :9009 and carries the exchange over it as FNWP frames."
