# T5: one monitor truth, and web pages that describe what the system does (2026-10-12)

Not committed. Against T4c (546df37). 110 paths in `git status`: 61 modified, 41 deleted, 8 new (etc/sudoers.d/,
once.py, test_snapshot_view_oracle.py, frognet_node.inc.php, getSnapshot.php, T5-BRIEF.md, t5-logs/, this file).

## Changes (one line each, with the reason)

Monitor data contract
- var/www/html/frognet_node.inc.php (new): one function per snapshot field, each with one source per mode (the header
  gives a table: field × region/LAN-only → file). The brief asks for one source per field.
- var/www/html/getSnapshot.php (new): serves `fn_snapshot()` (build, mode, ponds with the forward pond marked,
  members with role/alive/source, hub link with the wg handshake age, elections, sources, errors). This is the one
  per-node endpoint.
- getHosts.php and frognet_echo.php: now call fn_host_rows / fn_self_echo, with the same output as before. A page
  can no longer work a field out its own way.
- graph_apply._write_hosts_json: adds a guid to each region row, and graph_apply_oracle gets one more check. The
  snapshot's members carry the guid.
- etc/sudoers.d/frognet-snapshot (new; installer D5 and header.sh set 0440 and run visudo, and a fragment visudo
  refuses is removed and the install stops): www-data may run exactly `wg show all latest-handshakes`. The hub link's
  age comes from the kernel. handshake_rtts.json is 0600, so www-data cannot read it.
- **(resumed) fn_ponds: the forward pond's area now comes from facts.json `pond`, not site.env.** Before this, G3
  showed `area ""` and the error `site.env names no RINA_AREA`. site.env is 0600 root because it holds the site key,
  so www-data cannot read it. facts.json `pond` is the daemon's own RINA_AREA, and region.py writes it.
- (resumed) frognet_node.inc.php header: the sudoers file it names is now frognet-snapshot. It said frognet-setup,
  which is the wrong file.

Monitors
- Python: discovery.parse_snapshot/fetch_snapshot/hosts_of; identity.parse_echo_line/dot_one_of (their absence made
  the py parser oracle FATAL at T4c); a title line plus mode/build/ponds/hub lines; elections taken from the snapshot
  (the /etc/hosts reader is gone, so there is one source); `--once` (once.py) prints one frame. The brief asks for a
  one-shot mode.
- C++: parseSnapshot/NodeSnapshot and Client::snapshot/hostsOf. discoverHosts and the /etc/hosts databasehost read
  are gone. Both dashboards get titleText/nodeLines, and `frognet_monitor snapshot` prints one frame. Same contract.
- C#: Parsers.ParseSnapshot/TitleText/NodeLines, Client.SnapshotAsync/HostsOf (DiscoverHostsAsync and the /etc/hosts
  read are gone), the card header, `frognet-monitor snapshot`, and a demo with a sample snapshot. dotnet 8 exists on
  this host, so it was built.
- parser_vectors.json: 8 snapshot cases added, and `brokerhost` renamed to `otherhost`. The new fields are covered,
  and the monitors use no broker words.
- usr/local/bin/frognet_monitor (the launcher) passes its arguments through, so `--once` reaches the monitor.

- index.php is the node landing page (name, .1, mode, build; links to setup, dashboard, getSnapshot.php and FD&F).

- 28 web files with no caller deleted, plus PropogateHost, propogateMergeGuid.bash and var/www/html/frognet_monitor.
  Callers were checked in the tree, frognet-android and the Windows bridge (re-checked on resume: no remaining

- admin-site.conf, devices-site.conf, var/www/www_admin and frognet-dashboard.service deleted, along with their

## Found, not done

- **fln_dashboard32.html still draws the echo-derived uplink model.** It builds EXTERNAL edges host → Internet and
  child → parent, an egress BFS chain (~l.866–960), route-mode egress drawing (~l.1287–1360), and the status bar
  shows "N uplinks". Ponds and hub links were added next to this model, not in place of it. Replacing it means
  rewriting the three-views egress model and its oracle. In practice the child → parent edge never fires: echo
  fields 3 and 4 are the node's own upstream addresses, not a parent's .1.
- fln_dashboard32.html's refresh `catch` puts the previous HOSTS/NODES/EDGES back, so after a failed refresh the map
  keeps the last picture while the header says getSnapshot.php did not answer. This existed before T5.
- Nothing on a node starts the FD&F web view on :8090. It is a manual `php -S` (README). Until someone runs it, the
  "region members (FD&F)" link on the dashboard and the landing page leads nowhere.
- getHosts.php's LAN-only rows say `alive:false` (their old shape), while the snapshot's members say alive:true. The
  monitors and the dashboard read only the snapshot.
- databasehost.conf (*:80) and the *:443 vhosts are still enabled, and Apache listens on 8080/8443 only, so they are
  unreachable.
- frognet-dbhost-advertise.service fails in the first minutes after a boot (as T4a found).
- The snapshot's pond `config` reads `reach none, map refused` from the RAM manager's pond/config/net cell. It is
  shown as published, and nobody has checked whether that is what the region intends.
- The C++ and C# monitors are not built on nodes. Their G1 and G3 frames came from host builds pointed at each node.
